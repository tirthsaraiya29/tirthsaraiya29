01. System architecture

Whisk is a Kotlin Android application targeting API 26+ with a Jetpack Compose UI and Room-backed local workspace. Its Gradle configuration includes AndroidX, Compose, Room/KSP, DataStore, coroutines, serialization, OkHttp, WorkManager, Android security libraries, LiteRT-LM and ONNX Runtime dependencies.

Compose UI → domain/use-case layer → Room / DataStore persistence; AI workspace routes requests to local runtime or configured remote providers; MCP client mediates tool discovery and calls.

02. Component responsibilities

  • Presentation: Jetpack Compose and Material 3 screens.
  • Persistence: Room database and DataStore preferences.
  • Background work: WorkManager and coroutine-based tasks.
  • AI: local LiteRT-LM integration plus configurable remote-compatible provider paths.
  • Developer tooling: GitHub surfaces and an MCP client with explicit approval for write actions.
  • Vault portability: ZIP export/import with path traversal sanitization and manifest validation.

03. Interfaces and protocols

  • Android application targets SDK 37 and has a documented minimum SDK of 26.
  • Room is accessed through Kotlin data and persistence layers; KSP provides compile-time database code generation.
  • Remote model providers use HTTP-compatible APIs; local inference is delegated to the on-device runtime.
  • MCP uses JSON-RPC tools/list and tools/call, with sensitive write tools gated by user approval.

04. Runtime and data flow

The application is designed around local-first note access with AI features layered on top. The provider selection and embedding pipeline are under active verification; keep user-facing descriptions at the capability level until the exact implementation is confirmed.

05. Security considerations

The README documents ZIP path traversal checks and SHA-256 manifest validation, approval gates for write/destructive MCP actions and Android security/biometric dependencies. Do not infer a complete encrypted-vault or zero-trust guarantee unless the current code and threat model support it.

06. Build and validation

The app module uses Gradle Kotlin DSL, Android Gradle Plugin aliases, Kotlin Compose/serialization plugins and KSP. The inspected app configuration sets compile/target SDK 37, min SDK 26 and Java 17 source/target compatibility.

For an interview or technical review, use the repository's current build files, automated checks, release notes and source as the authoritative evidence for what is implemented at a particular commit.

07. Known limits and claims discipline

The embedding provider was previously found to use a feature-hashing path rather than the MiniLM semantic pipeline described in older material. Do not publish MiniLM as a verified shipped runtime until source code and tests prove it.

These notes are intended to support a serious technical discussion. They distinguish documented design intent from independently verified production guarantees.

Documentation is versioned with the portfolio. Repository source and release notes take precedence when implementation details change.
