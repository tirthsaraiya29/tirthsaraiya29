01

Four domains, one habit

Systems programming, cybersecurity, AI engineering and application development sound like four different jobs. In practice the work keeps landing in the same place: a boundary, and the question of what has to be proven before anything crosses it.

A phone proving itself to a Windows logon desktop. A portable executable proving its Authenticode signature before it is allowed to run. A spoken request proving it maps to exactly one operating system action, or asking for clarification instead of guessing. A sixteen gigabyte weight file proving it will fit in VRAM before anybody downloads it.

The languages keep changing. The shape does not.

Project 01 · Active

Tether

An Android phone as a cryptographic trust anchor for a Windows workstation. Unlock, lock, panic-lock and remote control over local Wi-Fi, with no cloud relay.

The problem

Windows sign-in is not an ordinary API surface. The tile a user clicks lives inside a COM DLL loaded by Winlogon on the secure desktop, and the process that knows whether the phone is present runs as a service in Session 0, deliberately isolated from everything the user can see. Bridging those two without opening a hole in either is most of the work.

How it is bridged

  • TetherCredentialProvider, a native C++ implementation of ICredentialProvider, registers into the logon UI and installs to System32.
  • Tether.CommunicationService holds the TLS listener, the paired-device registry, the trust store and the capability router.
  • Tether.SessionHelper.exe is launched into the active session through WTSGetActiveConsoleSessionId, WTSQueryUserToken, DuplicateTokenEx and CreateProcessAsUser, so session-bound actions can run at all.
  • Three named pipes carry traffic between them: TetherPipe for control and events, TetherUiPipe for diagnostics in byte mode, and Tether.InputPipe for remote input.
  • Five engines sit behind an in-memory event bus: trust state, panic, recovery, enforcement and pairing.

Cryptographic identity

Android private keys are generated inside the Android Keystore under the alias TetherIdentityKey_v1 with StrongBox protection where the hardware supports it, and never leave the enclave. They sign device-unique nonces with SHA256withECDSA. Windows holds a matching identity certificate. Every command payload carries a monotonically increasing request identifier, a UTC timestamp validated against a thirty second drift window, and an ephemeral challenge nonce.

Hardening ledger, release v1.2.3
  • Structured exception handling and full E_POINTER / E_INVALIDARG validation on every public COM method boundary, so no unhandled exception can cross into Winlogon.
  • SecureZeroMemory over the full buffer extent before every CoTaskMemFree of a plaintext password, across four separate code paths.
  • Global named events rewritten to the SDDL string D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;GR;;;AU) and opened with TryOpenExisting requesting only the minimum rights, which fixed an ACCESS_DENIED on WRITE_DAC for standard-user processes.
  • Existing events are re-stamped with SetKernelObjectSecurity so weaker DACLs left by older versions are upgraded in place.
  • An explicit deny ACE for the Anonymous SID on every NamedPipeServerStream, alongside the existing Network SID deny.
  • Application launch hardened against command injection: control characters rejected, shell metacharacters blocked, interpreters blocklisted by name and by extensionless name, and dangerous script extensions refused.
  • cmd.exe /c start replaced by a direct explorer.exe launch, and powercfg calls moved from string Arguments to the array-based ArgumentList.
  • Credential vault secrets moved to a dedicated Secrets registry subkey with a hardened DACL recorded as VaultDaclVersion=2, payload wrapped in CryptProtectData with a system-bound entropy string.
  • Password verification uses PBKDF2-HMAC-SHA-256 at 600,000 iterations or PBKDF2-HMAC-SHA-512 at 210,000, compared in constant time, with automatic upgrade of the legacy sha256-v1 format on next success.

What the phone can do

Eight capability domains: low-latency desktop streaming as multipart MJPEG with window targeting, per-application Core Audio volume and endpoint switching plus SMTC media transport, a multi-session terminal across PowerShell 5.1, Command Prompt, PowerShell 7 and WSL, a bidirectional notification bridge, file management with Recycle Bin integration and resumable chunked transfers verified by SHA-512, hardware telemetry and battery health through WMI, window and Start Menu management, and scheduled automation recipes gated on battery level, charging state or process presence.

Status, stated plainly

Tether is beta software under active development. Its own documentation says it has not undergone an independent security audit and should not be relied on to protect sensitive systems without one. That notice is deliberate and it stays in the README.

Project 02 · Active

Pico

A local-first, voice-only desktop assistant in idiomatic Rust. It selects operating system actions by retrieval and calibrated probability instead of running a generative model.

Why not a language model

Two traps sit on either side of this problem. A cloud assistant records audio, ships it to a third party and adds a network round trip to the act of muting a speaker. A local generative model hallucinates filesystem paths, invents flags that do not exist, and spends seconds and gigabytes of VRAM producing a single tool call.

Pico takes neither route. It classifies intent, retrieves candidates from an inverted BM25 index and a dense subword embedding space, scores them with a multi-feature cross-encoder combining intent affinity, semantic overlap, lexical overlap and contextual history, then converts those scores into probabilities with Platt scaling fitted against held-out validation data. Softmax alone does not produce reliable probabilities, and an assistant that is confidently wrong about delete_file is worse than one that asks.

Security posture

  • Canonical path sandbox rejecting traversal, symlinks and junctions, NTFS alternate data streams, DOS device namespaces such as CON and NUL, and UNC paths.
  • Anti-SSRF validation blocking loopback, RFC 1918 ranges and the 169.254.169.254 metadata endpoint.
  • Arithmetic through a zero-shell Pratt recursive-descent parser with depth and numeric bounds, never through PowerShell or bash.

Continuous on-device learning

Interactions, corrections and execution outcomes land in an on-device SQLite experience store. Label weights are 2.0 for a user correction, 1.0 for explicit feedback and 0.5 for execution outcome. Bounded weight clipping and rate limits guard against poisoning, and a promoted checkpoint can be rolled back instantly if a regression appears.

Structure

Eleven crates separating audio, voice, inference, decision, learning, memory, tools, platform, security, core and orchestration, plus two binaries: pico-cli and pico-desktop. The desktop app is a native egui and eframe window with no Chromium, no webview and no local server.

Project 03 · Active

Vantor

A hardened Windows-only antivirus and endpoint detection solution built on defence in depth, with scanning, protection and interface split into four decoupled components.

The separation is the design

Nothing in Vantor trusts the layer above it. The scanner runs as NT AUTHORITY\SYSTEM inside a pure C++ Win32 service that no user process can write to. The signature backend runs as a separate gRPC daemon. The Qt interface talks to both, and if the gRPC channel is unavailable it falls back to a restricted named pipe rather than failing open.

Signature lookup

The store is hybrid: SQLite for durable records and a memory-mapped Bloom index over signatures.idx for fast negative answers before any disk read. Archives are inspected without decompressing them. ZipBombDetector rejects anything with a compression ratio above 10.0x, a member larger than 1 GB, or more than 10,000 entries.

Assuming the binary is being attacked

The anti-tamper subsystem treats its own process as hostile territory: WinVerifyTrust Authenticode checks on loaded PE modules, a runtime self-hash of the in-memory .text section to catch code patching, inline hook detection on Win32 API prologues, anti-debug across PEB flags, NT debug ports, hardware breakpoint registers Dr0 through Dr3 and ThreadHideFromDebugger, RDTSC timing analysis and CPUID hypervisor detection, and a watchdog that restores corrupted files from a protected backup.

Every binary is compiled with Control Flow Guard, high-entropy ASLR and DEP. Quarantined samples go into an AES-256-GCM vault under a DPAPI machine-protected master key. Configuration is DPAPI-encrypted. Real-time protection watches the filesystem through ReadDirectoryChangesW.

Interface and build

The Qt client is high-DPI aware, frame-rate limited to a smooth 60 FPS at under one percent idle CPU, and supports drag-and-drop scanning, an encrypted quarantine browser and policy sensitivity controls. Packaging runs through a WiX toolset MSI, with a GitHub Actions workflow handling build, test, signing and installer production, and a GoogleTest-compatible suite for the backend.

Licensing note: the repository carries an all-rights-reserved notice rather than an open-source licence, which is stated here rather than guessed at.

Project 04 · Active

Whisk

An offline-first knowledge workspace and developer suite, native to Android. Bidirectional links, a spatial canvas, on-device vector search and a hybrid local plus cloud model workspace.

Search that is actually local

Semantic search on a phone is usually a stub that calls a server. Whisk runs sentence-transformers/all-MiniLM-L6-v2 through ONNX Runtime on the device: a full BERT WordPiece tokenizer against the 30,522 token vocabulary, attention mask handling, mean pooling, and L2-normalised 384-dimensional vectors. Lexical results from FTS4 and vector results by cosine similarity are fused with Reciprocal Rank Fusion, so a query matches on exact wording and on meaning at once. Indexing is thread-safe and transactional.

Models, hybrid by design

Open-weight models run locally through LiteRT-LM with no cloud latency and nothing leaving the device. When online, the same context assembly feeds OpenAI, Google Gemini, Anthropic Claude, OpenRouter or a custom HTTPS endpoint. Active notes, linked documents and retrieved chunks are injected into the prompt context. Streaming responses persist incrementally and recover from process death.

The workspace itself

A dual-mode Markdown editor switching between raw and rendered, syntax-aware code blocks with language labels, copy actions and line numbers, bidirectional [[wikilink]] discovery with backlink resolution, a global and local 2D knowledge graph with pan, zoom and distinct node classes for notes, tags and relationships, an orphan finder for unlinked notes, and an infinite spatial canvas where cards and containers keep coordinates in Room without altering note contents.

Developer surfaces and portability

A GitHub explorer for repositories, issues, pull requests and commit history sits next to a Model Context Protocol client. Write and destructive tools are detected automatically and require explicit approval before execution. The whole vault exports and imports as a ZIP with Zip-Slip path traversal sanitisation and SHA-256 manifest validation.

Project 05 · Active

Inferra

A pre-flight check for local AI. Work out VRAM fit, memory bounds and token throughput from a phone before downloading a single byte of weights.

The waste it removes

Downloading a 16 GB GGUF or EXL2 file takes real bandwidth and real time. Discovering afterwards that the GPU triggered layer offloading, truncated the context window to 2,048 tokens, or throttled to two tokens per second is expensive. Inferra runs the arithmetic first.

The model

Total requirement is the sum of quantised weights, KV cache as a function of context length, layer count, head count and head dimension, CUDA context overhead, and a peak activation buffer. The fit engine predicts VRAM and RAM pressure, layer offload ratios and tokens per second from GPU architecture and memory bandwidth in GB/s. KV cache scales to 128k tokens and beyond under FP16, Q8 or Q4 cache quantisation.

Decisions it supports

  • A quantisation explorer comparing memory footprint against perplexity delta across GGUF Q2_K through Q8_0, AWQ and EXL2.
  • A lineage tree tracing a base model through instruction tuning, chat alignment, community quants and LoRAs.
  • Side-by-side comparison of up to four models on active parameters, MoE top-k activation, MMLU-Pro, GSM8K and HumanEval scores, and licence constraints.
  • A desktop dispatcher that pairs companion nodes over local HTTP or HTTPS on port 8443, tests reachability and sends the download job to the rig instead of the phone.

Engineering

Clean Architecture with the fit mathematics isolated in domain/usecase as HardwareFitCalculator and MemoryEstimationEngine, stateless Compose screens, a Room catalog, Ktor and Retrofit with kotlinx.serialization, WorkManager for background metadata sync and download dispatch, and catalog ingestion in Python.

Honesty note: these are modelled estimates derived from architectural parameters, not measured runs. The README carries an open call for real hardware profiles and empirical tokens-per-second verification, including for Apple Silicon unified memory, Intel Arc, AMD ROCm and Snapdragon X Elite.

Project 06 · Archived

Keel

A Rust coding harness that was meant to own the engineering process while models stayed replaceable. Archived at alpha in September 2026 and kept as a design record.

The premise was that an LLM treated as a chatbot writes code, while an LLM treated as a worker inside a deterministic workflow builds software. Keel was to be the workflow: an orchestrator, state machine, policy engine and event system around swappable model runtimes for Ollama, GGUF and OpenAI-compatible endpoints, a context engine, and a tool engine for files, shell and git. Tests would be reviewed by an independent model, then locked against further model modification, executed independently, and failures either repaired or escalated to a different coding model, with a commit per completed phase.

The README opens by saying it is a vision pending implementation. It was archived rather than left to look finished, which is the correct outcome for a design that did not reach code. It stays in this portfolio for that reason.

About

I would rather ship a small system that states its own limitations than a large one that implies it has none.

I am a software developer in India working across the whole distance from a COM DLL loaded by Winlogon to a Jetpack Compose screen. The projects are self-directed: no team, no client, no product organisation behind them. What they share is a finishing habit.

Each one ships with its own installer, its own CI workflow, its own issue templates, its own security policy and its own release notes. The Tether release notes run to thousands of words and list the files changed, the tests added and the things still unverified. The Pico README names the exact processor, memory and operating system its benchmarks were measured on. Keel was archived rather than left looking complete.

That is not modesty, it is engineering. Security software that overstates its guarantees is worse than no software, because the user has stopped checking. Saying "this has not had an independent audit" in the README is the same discipline as validating a null pointer before dereferencing it.

The technical centre of gravity is the boundary: what crosses it, what proves it is allowed to, and what happens when the proof fails. Credential providers and named-pipe ACLs, TLS handshakes and replay windows, path sandboxes and SSRF filters, retrieval thresholds and clarification prompts, VRAM budgets and offload ratios. Different layers, one question.

What this page does not claim

  • No employment history, client work or team experience is listed, because none is being claimed here.
  • No education or certifications are stated, because they are not published in the source material this page was built from.
  • No security audit, compliance certification or performance guarantee is asserted for any project.
  • Tether and Vantor are pre-audit beta software by their own documentation. Neither should protect a sensitive system today.
  • Every benchmark on this page is quoted from a project README with its source and hardware named. Nothing was re-measured or estimated for this site.
