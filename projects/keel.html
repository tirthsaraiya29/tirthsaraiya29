At a glance

A Rust coding-harness concept that treats language models as replaceable workers inside a deterministic engineering workflow for planning, implementation, testing and review.

The problem

An AI coding tool can generate patches without owning the engineering process around them. A more reliable harness needs explicit phases, state, policies, tests and escalation paths rather than treating every model response as a finished result.

Engineering approach

Keel's documented vision wraps replaceable models in an orchestration layer with a state machine, policy engine, event system, context engine and tool engine. The repository is explicitly marked as an alpha vision pending implementation and is archived.

What the project explores

  • Goal-to-plan workflow concept
  • Deterministic orchestration around replaceable models
  • State machine and policy engine
  • Model runtime abstraction
  • Tool execution and context management concepts
  • Testing, review and repair loop described in the vision

Architecture at a glance

User goal → orchestrator / state machine → planning and policy → model worker + context engine → tools → tests and independent review → phase completion.

Engineering decisions

  • Keep the engineering workflow in the harness rather than delegating control to a model.
  • Make model providers replaceable.
  • Represent implementation progress as explicit state and events.
  • Treat testing and review as part of the workflow, not optional afterthoughts.
Status and scope. Keel is archived at the alpha/vision stage. Its README explicitly says the architecture is a vision pending implementation. This page describes the design, not a shipped autonomous coding agent.
