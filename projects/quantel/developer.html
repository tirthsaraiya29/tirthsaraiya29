Under the hood.

A technical reading of Quantel AI: its architecture, component boundaries, interfaces, runtime behavior, security assumptions and implementation constraints.

01. System architecture

The repository contains a static `index.html` and `script.js` with a browser-side chat interface. The page includes external Markdown and syntax-highlighting libraries and Tailwind CDN usage.

Static HTML/CSS interface → vanilla JavaScript state and request handling → local-model proxy → message rendering and browser-side persistence.

02. Component responsibilities

  • index.html: layout, chat shell, model selector, persona modal and visual styling.
  • script.js: model selection, send lifecycle, conversation state, attachment state and response presentation.
  • Browser-side persistence: state is designed to keep conversations available across sessions.
  • Model proxy: requests are directed through a configurable service endpoint rather than treating the browser UI as the model runtime.

03. Interfaces and protocols

  • Markdown output is rendered through Marked; code blocks use Highlight.js.
  • Model access is mediated by a proxy endpoint configured in the client.
  • The UI supports image attachment state, but the actual model endpoint must be configured to accept the payload format.
  • The repository does not currently document a stable external API contract.

04. Runtime and data flow

The JavaScript client keeps active model, current conversation, message list, persona/system prompt and in-progress attachment state. The request lifecycle disables duplicate sends while a response is being processed.

05. Security considerations

Do not expose a private network address, internal proxy hostname, API key or unrestricted local model endpoint in a public browser application. Treat rendered Markdown and model-generated content as untrusted input; sanitize HTML before inserting it into the DOM.

06. Build and validation

The documented implementation is a static browser page with no package-managed build step. External scripts/styles are loaded from CDNs in the current HTML and should be pinned or self-hosted before a hardened production deployment.

For an interview or technical review, use the repository's current build files, automated checks, release notes and source as the authoritative evidence for what is implemented at a particular commit.

07. Known limits and claims discipline

Prototype status. No maintained deployment, test suite or stable backend contract is claimed.

These notes distinguish documented design intent from independently verified production guarantees.
