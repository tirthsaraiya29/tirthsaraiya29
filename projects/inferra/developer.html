01. System architecture

Inferra is a Kotlin Android project whose core is a pre-flight model-fit calculator. The README describes support for multiple quantization families and estimates for device memory pressure and throughput.

Model metadata + quantization profile + hardware profile → weight / KV-cache / runtime-memory estimates → fit and offload analysis → download decision

02. Component responsibilities

  • Model metadata and quantization descriptors.
  • Hardware profile and available-memory inputs.
  • Weight memory estimator.
  • KV-cache estimator parameterized by context and cache precision.
  • Runtime overhead and activation reserve.
  • Fit/offload result presentation and optional LAN dispatch workflow.

03. Interfaces and protocols

  • Android UI is built with Kotlin and Jetpack Compose.
  • The documented model formats include GGUF, AWQ and EXL2 families.
  • The fit model combines quantized weight size, KV cache and runtime buffers rather than using a single parameter-count heuristic.
  • Remote dispatch is described as a local-network handoff to a desktop/rig.

04. Runtime and data flow

The calculation is a pre-flight model, not an inference engine. It produces feasibility estimates to guide a later model download and launch decision.

05. Security considerations

Treat remote dispatch as a privileged action boundary. Validate destination pairing, transfer authentication and path handling against the current implementation before advertising the dispatch path as secure.

06. Build and validation

The repository README identifies an Android API 31+ Kotlin/Compose application. Use the current Gradle files and release configuration for exact SDK and dependency versions.

For an interview or technical review, use the repository's current build files, automated checks, release notes and source as the authoritative evidence for what is implemented at a particular commit.

07. Known limits and claims discipline

Predicted tokens per second are approximate. The estimate cannot fully capture runtime-specific kernels, driver versions, quantization implementations or thermal throttling.

These notes are intended to support a serious technical discussion. They distinguish documented design intent from independently verified production guarantees.

Documentation is versioned with the portfolio. Repository source and release notes take precedence when implementation details change.
