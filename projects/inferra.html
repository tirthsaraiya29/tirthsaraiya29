At a glance

An Android companion for evaluating whether open-weight AI models are a practical fit for a device or workstation before spending time and bandwidth downloading them.

The problem

A model download can consume many gigabytes and still fail to fit available VRAM, force heavy CPU offload or leave too little memory for a useful context window. Hardware feasibility should be estimated before the download, not discovered afterwards.

Engineering approach

Inferra models the main memory costs of local inference: quantized weights, KV cache, runtime/context overhead and activation buffers. It uses hardware capability and memory-bandwidth estimates to reason about fit, offload and approximate throughput.

What the project explores

  • Model and quantization exploration
  • VRAM and RAM fit estimation
  • KV-cache sizing across context lengths and cache formats
  • Layer offload and throughput estimates
  • Hardware-aware pre-flight workflow
  • LAN-based download dispatch described in the project README

Architecture at a glance

Model metadata + quantization profile + hardware profile → weight / KV-cache / runtime-memory estimates → fit and offload analysis → download decision

Engineering decisions

  • Account for the KV cache instead of comparing only model weight size.
  • Treat quantization format as a first-order input to memory estimation.
  • Separate fit prediction from the later runtime execution of a model.
  • Make the smartphone a planning interface for local AI hardware.
Status and scope. Throughput figures are estimates, not measured guarantees. Actual inference speed depends on backend, drivers, runtime, memory bandwidth, thermal limits and workload. The project is exploratory and is not a substitute for benchmarking the target machine.
