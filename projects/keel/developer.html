01. System architecture

Keel is a Rust project whose README explicitly positions it as an alpha vision rather than a completed implementation. The system is designed around a deterministic orchestrator and replaceable model workers.

User goal → orchestrator / state machine → planning and policy → model worker + context engine → tools → tests and independent review → phase completion.

02. Component responsibilities

  • GUI: intended entry point for goals and progress.
  • Core orchestrator: coordinates phases and workers.
  • State machine: represents workflow progress and transitions.
  • Policy engine: constrains model and tool operations.
  • Event system: records workflow updates.
  • Model runtime, context engine and tool engine: intended modular subsystems.

03. Interfaces and protocols

  • The README describes model backends such as Ollama, GGUF and OpenAI-compatible endpoints as planned runtime options.
  • Tool categories in the vision include file, shell and Git operations.
  • The architecture is conceptual; no stable public API contract should be inferred from this description.

04. Runtime and data flow

The intended lifecycle progresses from goal analysis and plan generation through staged implementation, locked tests, independent execution, repair and review. The README frames the harness as the owner of this process.

05. Security considerations

The proposed policy engine and tool engine would be security-critical. A real implementation would need explicit filesystem boundaries, command allowlists, confirmation policy, secret redaction and auditability. These are design requirements, not claims of completed controls.

06. Build and validation

The repository is Rust-based. Treat the existing source and commit history as an alpha snapshot; do not imply that the complete workflow described in the README is implemented.

For an interview or technical review, use the repository's current build files, automated checks, release notes and source as the authoritative evidence for what is implemented at a particular commit.

07. Known limits and claims discipline

Archived at alpha. Vision-only documentation; not a shipped autonomous software engineering agent.

These notes distinguish documented design intent from independently verified production guarantees.
