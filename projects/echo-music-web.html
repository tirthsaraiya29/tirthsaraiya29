At a glance

A public Echo Music monorepo fork that brings together the Android application source and a separately engineered React/TypeScript web client. The web work targets desktop and tablet browsers rather than wrapping the Android UI.

The problem

A mobile-first music product does not automatically translate into a good browser experience. Desktop and tablet users need browser-native navigation, audio controls, persistence and integrations, while the Android application should retain its own platform-specific implementation.

Engineering approach

The fork keeps the Android source in its own Echo-Music workspace and introduces a separate Echo-Web application. The web client uses React and TypeScript with a Hono proxy service, browser audio APIs and IndexedDB-backed persistence. The associated upstream restructuring proposal is PR #911 and remains open at the time this portfolio snapshot was prepared.

What the project explores

  • Separate web client for desktop and tablet browsers
  • Web Audio playback engine with dual-deck and crossfade design
  • Local Hono proxy for catalog and audio-stream routes
  • IndexedDB persistence for local library and application data
  • Search, playlists, synced lyrics and provider integrations described in the project docs
  • Collaborative upstream proposal to introduce the web client and monorepo structure

Architecture at a glance

Browser UI (React / TypeScript) → query and state layers → Web Audio playback engine + Dexie IndexedDB; API calls route through a Hono server/proxy; Android source remains in a separate workspace.

Engineering decisions

  • Build a browser-native client instead of embedding the Android UI in a web wrapper.
  • Keep platform-specific playback and lifecycle behavior separate across Android and browsers.
  • Use a small local API proxy for upstream catalog and stream interactions.
  • Keep persistent browser state in IndexedDB rather than relying on volatile component state.
Status and scope. The upstream restructuring PR #911 is open, not merged. The PR description credits collaboration with @yashsoni48. The Android subtree is relocated upstream source, not a claim that the Android application was independently authored in this project.
